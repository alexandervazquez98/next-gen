## [1.16.1] — 2026-09-07

### Added

- **MQTT audit trail for mapping lifecycle changes (#386, PR #449)**: every mutation to an MQTT mapping (create / edit / approve / revoke / threshold change) now emits an audit event persisted to the existing audit surface. `AUDIT_CONTEXT_ALLOWED_KEYS` in `backend/services/audit_service.py` extended with 8 mapping keys (mapping id, source device/metric, target CI/MetricDef, thresholds, changed_fields, before/after values) so operator actions are reconstructible post-hoc. New `_enforce_manage_with_audit` denial helper emits the audit row even on authorization failures. Operator-facing denial paths are also audited. 45 tests cover the full lifecycle (`test_audit_router.py`, `test_audit_service.py`, `test_mqtt_mapping_service.py`).
- **MQTT frontend monitoring UX foundation — PR1 of feature-branch-chain (#385, PR #450 → tracker `feat/mqtt-385-frontend-ux`)**: new `/monitoring/mqtt` route surfaces bridge status and raw MQTT telemetry for operators with `MQTT_READ`. Foundation slice ships the route, permission gates, raw browse tab, bridge-status tab, and a `RawNonKpiBadge` that prevents raw MQTT from ever rendering as a KPI. Mapping lifecycle management UI (create/edit/approve/revoke/thresholds) is deferred to PR2, which will merge the tracker to `main` and close #385.
- **Stale event review reminders backend — PR1 of feature-branch-chain (#154, PR #451 → tracker `feat/154-stale-event-reminders`)**: events are never silently auto-closed, but forgotten OPEN/ACK events age indefinitely without visibility. This slice adds a schema-versioned, read-only detection surface plus quick-action endpoints (ack / assign / add-note) that PR2's frontend will consume. Detection uses a dedicated Neo4j read session with `default_access_mode=READ_ACCESS` (see `_NEO4J_READ_ACCESS` capture in `backend/services/stale_event_reminders.py`). 34 backend tests cover detection cypher, action endpoints, and edge cases.
- **MQTT operational smoke for subscriber runtime (#387, PR #448)**: new `scripts/mqtt-ops-smoke.sh` (POSIX sh) validates the subscriber runtime end-to-end against a real broker — connect, subscribe, receive, and last-message freshness — with `set -eu` fail-fast semantics and a trap-based rollback that never leaks broker credentials. Companion `scripts/test-mqtt-ops-smoke.sh` runs an offline forbidden-token test suite so the smoke cannot regress into printing secrets. Runbook documents invocation, expected output, and failure triage.
- **AI chat panel is now resizable (drag handle) and bumps base font size (#461, PR #464)**: the AI chat aside was hard-coded to `w-96` (~384px) with `text-sm`/`text-xs` typography, leaving operators with no way to widen it on large monitors and forcing scroll on smaller laptops. This change adds two new hooks — `useChatPreferences()` (single source of truth for panel state, persists width via `localStorage` with debounced writes, clamps to `[320, 720]` px, exposes a dormant `fontScale` for future font-scale UI) and `useResizableHandle()` (pointerdown/move/up drag math with listener cleanup) — wires a 6px `cursor-col-resize` drag handle into `App.tsx`, and bumps three typography classes in `AIAgentConsole.tsx` (message bubble `text-sm`→`text-base`, header `text-xs`→`text-sm`, input/placeholder `text-sm`→`text-base`). Below 768px viewport the panel auto-switches to a full-width overlay drawer (debounced `window.resize` listener, 250 ms). 19 new tests across 3 files; full frontend Vitest suite green at 609/609 across 75 files.

### Fixed

- **TimescaleDB `metric_values` hypertable now has a retention policy (#457, PR #463)**: `metric_values` was created as a TimescaleDB hypertable at `backend/repositories/metric_repo.py:18` but never received an `add_retention_policy` call, so it accumulated indefinitely — observed in production where `pg_dump -Fc` for `safe-rebuild.sh` went from <30 s on a fresh install to >5 min with dumps exceeding 250 MB. This change adds `backend/services/retention_service.py` with `apply_metric_retention()` (idempotent wrapper that catches `IntegrityError`/`ProgrammingError`, treats as success) and `run_metric_retention_cleanup()` (defensive re-apply via `timescaledb_information.jobs` query), wires it into the existing `backup_scheduler` as a 6 h `CronTrigger` job (kill-switch via `METRIC_RETENTION_ENABLED`, default interval `METRIC_RETENTION_DAYS=90` aligned with the audit + MQTT lifecycle retention windows), applies the policy on boot inside `create_hypertable` so fresh installs are bounded immediately, and retires the *"do not enable until benchmark and storage-growth evidence exists"* caveat in `docs/polling-pipeline-tuning.md` (that evidence is exactly what this PR provides). 22 strict-TDD tests + 10-test precedent regression sweep; full backend test suite green.
- **AI chat regex now recognizes Spanish verb conjugations (#458, PR #462)**: `infer_chat_intent.asks_to_list` and `infer_followup_intent.asks_availability` in `backend/routers/ai.py` were literal alternations against canonical verb stems only — conjugated forms like `verificación`, `verificando`, `monitoreando`, `chequeando` and phrasings using `tengo` / `tenemos` / `cuáles` bypassed deterministic harness selection and fell through to LM Studio with a generic "no harness result". Fix replaces the stems with `\w*` wildcards, adds the literal `tenemos` token (not covered by `tengo(s)?`), and adds `cu[aá]les?` to accept both accented and unaccented variants. Doc policy `backend/ai/policies/followup-intents.md` synced. 11 new parametrized tests in `backend/tests/test_ai_chat_service.py` (full suite 91/91).
- **Neo4j CypherSyntaxError on `NULLS LAST` no longer breaks event queries silently (#459, PR #462)**: `backend/services/event_service.py:_fetch_page` used `ORDER BY e.created_at ASC NULLS LAST`, but Cypher 5 (Neo4j 5.x/25.x) does NOT accept explicit `NULLS FIRST` / `NULLS LAST` — NULL ordering is implicit (ASC = NULLs last, DESC = NULLs first), so the clause was both invalid syntax AND redundant. The clause is removed. The hidden second-order failure was that `event_batch_pruner` in the same file wrapped every chunk failure in `try/except Exception` and re-emitted a `CypherSyntaxError` as a normal SSE `data:` chunk instead of failing loud, so a syntax regression in production would silently serve stale data with no error to the operator. Fix adds an `is_cypher_syntax_error()` predicate that closes the SSE stream with a terminal `error` chunk + `ERROR` log, registers `verify_cypher_smoke()` in `backend/main.py` startup (NOT in `/system/status` polling — guarded by `DISABLE_NEO4J_SMOKE=true` kill switch), and ships a CI regression scan that rejects any reintroduction of `NULLS\s+(FIRST|LAST)` anywhere in the tree. 22 focused tests + a 154-test adjacent sweep in `backend/tests/test_event_batch_pruner.py` and the new `backend/tests/test_neo4j_smoke.py`.
- **LM Studio HTTP 400 now surfaces as a meaningful 502 with the upstream reason (#460, PR #462)**: `_post_lm_studio_chat_completion` in `backend/services/ai_chat_service.py` caught `urllib.error.HTTPError` (subclass of `URLError`) inside a single `except URLError` arm, throwing away `exc.code` and `exc.read()`. The router then mapped every failure to `502 LM Studio is unavailable`, indistinguishable from a real network outage. Split the except chain so `HTTPError` is handled BEFORE `URLError`; new `LMStudioRequestRejected(LMStudioError)` carries the upstream HTTP status + a 512-byte body preview; router arm maps to `502 LM Studio rejected the request: <reason>`. 13 new parametrized tests in `backend/tests/test_ai_chat_service.py` (full suite 105/105).

## [1.16.2] — 2026-09-11

### Fixed

- **`COOKIE_DOMAIN` is now documented in `.env.example` (#466, PR #481)**: when operators deploy next-gen on a LAN/IP host (e.g. `http://192.168.1.X:3000`), browsers reject auth cookies whose `Domain=localhost` attribute was set because `COOKIE_DOMAIN` was never documented in `.env.example`. The override already exists in `backend/routers/auth.py` (lines 64-67) but the env var was undocumented so deployments silently inherited the legacy `FRONTEND_ORIGIN` hostname fallback. This change documents `COOKIE_DOMAIN=none` as the documented default with inline guidance for the three modes (`none`, exact hostname, empty/legacy). `scripts/validate-env.sh` handles the new var without code changes — it is non-sensitive, `none` is not in the unsafe-sentinel list, and the existing empty-value warning covers the legacy fallback case. Verified end-to-end on the test server: login → `Set-Cookie` headers carry `HttpOnly; Path=/api; SameSite=lax` with no `Domain` attribute (Host-Only), `/auth/users/me` returns 200, and `/auth/refresh` round-trips with a new `refresh_token` cookie.
- **`PydanticSerializationError` no longer breaks ITSM service-catalog writes (#473, PR #481)**: `POST/PUT /api/itsm/service-catalog` and `POST .../deactivate` returned HTTP 500 with `pydantic_core._pydantic_core.PydanticSerializationError: Unable to serialize unknown type: <class 'neo4j.time.DateTime'>` because Cypher stores `created_at`/`updated_at` via `datetime($x)` and the Neo4j Python driver returns them as `neo4j.time.DateTime`, which Pydantic cannot encode. New static helper `ServiceCatalogRepository._to_iso()` coerces any value exposing `.iso_format()` (Neo4j driver convention) or `.isoformat()` (stdlib `datetime`) through its stringifier; `None`, plain strings, and ints pass through untouched. Wrapped in `_record()` which is the canonical fix boundary — `bulk_create`, `upsert`, `update`, and `deactivate` all flow through it. Three regression tests in `backend/tests/test_service_management_pr2.py` cover neo4j.DateTime, stdlib datetime, and pass-through cases. Verified end-to-end on the test server: full CRUD lifecycle (POST → GET → PUT → deactivate → GET) returns 200 with valid ISO 8601 timestamps that parse cleanly with `datetime.fromisoformat`, and `updated_at` correctly advances on PUT.
- **Backend test suite now runs cleanly inside `nexgen_backend` (#474, PR #482)**: the previous setup reported **30 failed + 16 errors** from inside the backend container. The 16 errors were pure environment issues that masked the real regressions: (a) tests deferred-importing with `from backend.X import Y`, which couldn't resolve because the container has a flat layout (`WORKDIR /app` IS the backend, so `backend.X` looked for `/app/backend/X.py` — a path that doesn't exist), (b) `testcontainers[postgres]` was missing from the runtime image because `backend/Dockerfile` only installed `requirements.txt` not `requirements-dev.txt`, and (c) `pg_dump` was unavailable until `postgresql-client` was added (already shipped in main). This change (i) adds `pythonpath = .` to `backend/pytest.ini` and a self-referential `RUN ln -s /app /app/backend` in `backend/Dockerfile` so the nested test-import path resolves against the flat container filesystem without restructuring any test code or moving the production runtime tree, and (ii) installs `requirements-dev.txt` alongside `requirements.txt` so the full backend pytest suite — including the 4 `test_writer_advisory_lock.py` concurrency tests — has its dependencies inside the container. Verified end-to-end on the test server: `pytest tests/test_neo4j_write_guard.py tests/test_snmp_service_cypher_fallback.py tests/test_snmp_worker_cypher_fallback.py` now collects and passes all 19 tests inside the rebuilt image (was 16 errors + 3 failures). The two pre-existing auth test failures covered by #466/#473 still need their own fixes (separate scope).

## [1.19.3] — 2026-09-29

### Performance

- **Geo View no longer costs every operator a megabyte on page load (#527, PR #530)**: `frontend/components/MonitoringConsole.tsx` imported `VectorTileBasemap` statically, which pulled `maplibre-gl` — a WebGL renderer — into the entry chunk. The Geo View is one tab of the Event Console, so every operator downloaded ~1 MB they may never open. The import is now deferred with `React.lazy()` + `Suspense fallback={null}` at the call site, using the existing `GeoViewErrorBoundary` for chunk-load failures and Leaflet's own tile events for the loading state. The side-effect import of `@maplibre/maplibre-gl-leaflet`, which patches `L.maplibreGL` onto the shared Leaflet namespace, travels with the chunk; that is correct, because the component body calling `L.maplibreGL` only runs once the chunk resolves and both files share one `leaflet` instance. `frontend/vite.config.ts` is deliberately unchanged — its `optimizeDeps.exclude` is a dev-server pre-bundling concern, orthogonal to build-time code splitting. Measured with `vite build`, both ends reproduced independently in CI and in the test-mode report:

  | artifact | before | after |
  |---|---|---|
  | `index-*.js` (entry) | 2,854.68 kB | **1,819.57 kB** |
  | `VectorTileBasemap-*.js` (lazy) | — | 1,029.91 kB |
  | `index-*.css` | 189.38 kB | 106.23 kB |
  | `VectorTileBasemap-*.css` (lazy) | — | 83.15 kB |

  Main JS drops **1,035.11 kB (−36.2 %)**; total CSS is unchanged at 189.38 kB, with 83.15 kB of it now deferred. **Note for anyone comparing against issue #527:** its "~1.5 MB" acceptance criterion is not reachable — the measured floor is 1,807.75 kB — and the numbers above are the real ones. The issue's separate claim that `maplibre-gl` inflates the bundle by ~1 MB was accurate. A new behavioral test pins the deferral: it mocks `./VectorTileBasemap` and uses `vi.resetModules()` with a fresh dynamic import per test, so it fails against a static import rather than passing vacuously.

## [1.14.6] — 2026-08-14

### Fixed

- **SSE bulk-close endpoint no longer stalls the FastAPI event loop** (PR #429, replaces broken v1.14.5): `event_batch_pruner` in `backend/services/event_service.py` was an `async def` async generator that ran the bulk-close SSE stream on `GET /api/events/bulk/stream-progress`.
